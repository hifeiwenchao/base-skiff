# BaseSkiff macOS 原生迁移设计

状态：用户已确认并授权实施。2026-11-26。

## 目标与约束

用户已选择 macOS 使用 Swift / SwiftUI + AppKit，Windows / Linux 保留现有 Python / PySide6 版本。迁移以现有界面、交互和真实数据库功能为验收基线，不重新设计产品，不以演示数据代替服务集成。现有 Python 应用保留可运行，原生版通过完整验收后才作为 macOS 默认产物。

## 方案

已确定原生 UI 技术。实现建议：SwiftUI 承担窗口、工具栏、表单和状态组织；AppKit 的 NSOutlineView、NSTableView、NSTextView 承担大规模树、可编辑表格和 SQL 编辑器。数据库服务继续使用已有 Python 模块，作为随应用打包的无界面子进程，通过 stdin/stdout 通信，无 HTTP 服务、无浏览器、无 Qt 界面运行时。

替代方案是同时用 Swift 重写六种数据库驱动、SSH、凭据和二进制编解码，这会扩大行为差异和兼容性风险；嵌入现有 Qt 窗口则不能满足所选的 Swift 原生 UI。推荐只复用已经验证的服务层，完整重写 UI。

以下服务复用、通信协议和控件选择是实施建议，不代表用户已明确指定。

## 界面与交互基线

保持暖白 / 鼠尾草绿配色、侧栏、面包屑、常驻对象标签、数据 / 结构工作区和独立 Console。颜色从现有 theme.py 对照提取；默认侧栏 240、可调 200–560，字号 11–16、两档行密度保留。中文 / English 即时切换，不重置查询或草稿。

侧栏使用稳定节点身份增量更新；Redis 每次最多加载 500 个键，累计展示，展开目录不查询，选中键不自动滚动。大量数据不使用每行独立 SwiftUI 视图；表格只绘制可见单元格，大值预览限长但导出保留原文。对象标签保留分页、排序、选区、未提交修改和草稿；右键关闭当前 / 其他 / 全部，涉及修改仍先确认。

## 服务进程与类型协议

新增版本化消息协议，逐条包含协议版本、请求 ID、方法和参数；响应和进度携带同一 ID。仅显式注册的操作可调用，不允许通过方法名任意访问对象。日志走 stderr，stdout 只输出协议。进程仅继承必要环境，不在命令参数或日志中传凭据。

值使用显式类型标签保存 bytes/Base64、Decimal、日期时间、整数、UUID、BSON 等，字典采用键值对表示以保留非字符串键；不得用 default=str 或浮点数替代精确值。续载游标及并发快照使用进程内不透明句柄，绑定连接、DB 和操作类型；过期或进程重启必须刷新，不可静默复用。编解码、SQL 提示、结构草稿等纯逻辑同样在服务端复用。

后台执行不阻塞主线程，读取结果按来源工作区和请求代次投递，关闭标签或新查询后丢弃迟到结果。取消通道独立于任务队列，连接现有 CancellationToken；已经进入提交阶段不声称可撤销。限制并发、消息和预览大小；大结果分块传输，完整 CSV 由服务端流式处理，避免一次复制整个文件。写操作不自动重试；进程崩溃且提交结果不明时明确提示核实，保留本地草稿。

## 数据兼容

继续使用 ~/Library/Application Support/BaseSkiff 中的 metadata.sqlite、credentials.key 和 playground.sqlite，不访问钥匙串。兼容现有连接、Fernet 密码、历史、Console 文档、Redis 搜索收藏。复用现有服务以避免重复凭据实现。新设置采用可版本化格式，首次导入现有 QSettings 的语言、布局及工作区描述；迁移前备份，仅非破坏性添加，旧版仍可运行。测试和启动检查使用临时数据目录。不得在自动测试中改写用户真实连接或历史。

## 实施顺序与发布门槛

1. 固化截图、功能清单和协议，验证高精度 / 二进制往返、取消及现有数据兼容。
2. 完成原生窗口、连接和树导航、标签与网格、Console，再迁移结构 / 导入导出 / Redis / Mongo 交互。
3. 按清单逐项回归，包括大树 / 大字段、窄窗口、缩放、中文英文和后台迟到结果。
4. 打包 Swift 可执行程序及独立 Python worker，检查 worker 不包含 Qt、无外部 Conda / 源码路径依赖。
5. 使用独立 dist/build-YYYYMMDDHHMMSS/BaseSkiff.app，保留旧产物；启动检查使用临时目录。原生迁移期间可交付明确标注的独立预览产物，未通过全部门槛前不能替换默认 macOS 版本或声称迁移完成。

当前本机为 Apple Silicon，可验证 arm64 macOS；Windows / Linux 仍走现有构建，Intel macOS 需对应架构构建和实测，不宣称已验证。首个原生版以 macOS 14+ 为建议最低系统版本，使用平台可用性检查避免意外依赖新 SDK 独有接口；最终以实际依赖和构建结果核定。

## 实施审查补充

独立审查认为设计可进入计划。通信实现须增加版本握手、启动超时、崩溃检测、优雅退出、句柄释放和上限；采用有大小上限的分帧，分块响应包含序号与结束标志，并实施背压。工作区身份包含 lifetime token，关闭后重开同名标签不能接收旧结果。

性能验收与现版在同机同数据上比较：累计大量 Redis Key 后滚动 / 展开、1,000 行含大字段的绘制、频繁切换标签、输入与补全响应；记录数据量、耗时和内存，不以主观流畅替代证据。格式可编辑范围逐项对照现有 codec 测试，不擅自扩大可写格式。

设置导入记录迁移版本，原生设置采用独立命名空间，避免旧版退出时覆盖；共用服务元数据库保留现有事务与锁语义，并验证两个进程并发访问。迁移与备份时要求应用退出；不得在另一个客户端提交期间覆盖文件。
